M×N Vector Core

The vector core as the simulator now models it, drawn from the code in src/vector_core/v2 rather than from the plan. Decode 2 still issues packets. Each packet becomes one round for the four slots, and everything below the round queue is the new core. Run it with --vector-arch fu_groups.

Not yet as planned

  • Single mode only: one round per packet. Loop mode (resident slots repeating with a trip count) is the next milestone.
  • Mask registers are still tracked by decode 2's busy bits, not by the vector core's scoreboard.
  • When mv.stm and a compare write the same mask bank in one cycle, mv.stm goes first. The plan has the compare first.
  • Move-to-scalar reaches scalar writeback one cycle after its slot fires, not the same cycle.
  • Writeback priority is a fixed order; oldest-first is not built.
  • The activity view and the harness platform still use the v1 core.
